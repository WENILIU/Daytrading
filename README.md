# Daytrading — 台股開盤跳空反轉（Gap Fade v13）

當沖策略：交易**相對大盤**異常跳空的個股，賭散戶造成的超漲超跌在盤中回歸均值。
全部部位當沖平倉，零融資，整張交易，資金 450 萬。

## 策略流程（濃縮版，完整時間軸見 `STRATEGY_v13.md` 第 1 節）

```text
盤前   v13_factors.py --refresh（因子面板 + T-1 成交額）→ 處置股公告更新 → 讀淨值（回撤煞车用）
08:58  登入群益（CA 憑證）→ 載入 v13_model.pkl → 盤前裁剪：先砍掉成交額不足與處置股
09:00  掃全市場 3,307 檔（上市+上櫃，約 1.5 秒）
       market_gap = 0050 開盤跳空；adj_gap = 個股跳空 − market_gap
       SHORT adj_gap ≥ +1.5% ／ LONG ≤ −5.0%
       上限按方向分開：SHORT |adj_gap| > 4% 跳過、LONG > 8% 跳過（2026-11-01）
         SHORT 受「停損被漲跌停 cap 住」制約；LONG 受實測進場成本制約
       排除：開盤鎖死漲跌停、處置股、股價<30、T-1 成交額<1,000萬、無可借券、全額交割、零當沖量
評分   兩段式 HistGradientBoosting（逐年 walk-forward）→ pred_q 後 20% 丟棄 → 基礎部位 5/7/9/12%
倉位   × 漲停距離倍數（<1.5%→×10、<4.5%→×2.5）× 淨值回撤（>0.6%→×0.30、>1.2%→×0.12）× k_trail
       → 上限 min(25%×淨值, 開盤可成交額 10%) → 整張湊整 → 依 pred_q 由高到低填單
       → 總名義上限 1.90×淨值（需融資額度約 855 萬；往下退 1.75/1.50/1.00 回撤都不變）
         曝險 1.00→2.00 部位 MDD 恆為 −3.87%、參與率 p90 只從 6.6% 到 7.2%：
         這個旋鈕只增加檔數、不放大單量，所以只買報酬、不改變風險與成交假設
       開盤可成交額 = 0.1497 × T-1 成交額（實測中位數）。1 張超過它就跳過，超過就把單壓到它
下單   SendStockStrategyDayTrade 一張智慧單 = 進場 + 停損 + 停利 + 13:25 平倉，由交易所執行
       停損 = min(4%, 漲停價 − 1 tick) → 觸及漲跌停立刻停損，絕不被鎖、絕不隔天回補
       停利 = 12%（q1 ≥ 0.85 則 20%）
13:25  交易所自動平倉 → 零隔夜
盤後   更新淨值/高峰 → equity_state.json；EXECUTION RISK REPORT + exec_report_*.json + trading_logs/
```

**沒有筆數上限，資金就是筆數閘門**：訊號依 `pred_q` 排序後依序填單，總名義到上限就停。
實測平均 34 個候選/日 → 實際成交 9.4 筆/日，60% 的交易日現金用完（2021 年後 87-99%）。
加硬性筆數上限反而會砍掉低波動年裡真的能成交、有利潤的單，所以刻意不加。

**風控只有兩層**：淨值回撤縮倉、觸漲跌停即停損。
circuit breaker、vol targeting、direction-balance、`k_model` 都已實測否決（見 `STRATEGY_v13.md` 第 1 節末表）。

**進場方式已實測對照過（2026-11-01，1,907 筆真實訂單）**：開盤競價價、09:01 市價、09:01 掛限價在開盤價三種做法，同一批單、同一出場路徑，並先驗證 A 臂與日線回測 100% 一致（出場原因 99.9%、每筆損益差 0.0000%）。結論是競價進場比較好，但好在**不用付價差**（競價只有一個價格），不是好在有深度——競價金額只占 09:00 那根的 p50 51%，與 09:01 那分鐘同級。被動掛限價會變成虧損：成交率 70-79%，但成交的都是價格已經反向走的單（每筆 −0.43% 對照 +0.32%）。所以 live 走 09:01 限價，並按方向分開排除大 gap 訊號（SHORT >4%、LONG >8%）。完整對照與條件式成本表見 `STRATEGY_v13.md`「進場方式 A/B/C 的實測對照」。

**容量**：流動性是**單筆參與率上限**（開盤可成交額的 10%），不再是「T-1 成交額 < 5×淨值就跳過」
的股票門檻。舊門檻寫成淨值的倍數，淨值一大就砍股票而不是壓單量（14.4 → 4.7 筆/日），
450 萬實測代價 9 個百分點且回撤更差；2026-11-01 把部位釘死做對照後確認它也沒有買到
「零落差」，三條規則在報酬與回撤上都分不出差異（`LIVE_READINESS.md` §11.24）。
參與率上限的好處是它**不隨資金尺度變**：部位從 450 萬長到 13 億，參與 p90 恆在 10% 以內，
所以成交假設不會隨規模退化。股票池的底是固定 T-1 成交額 1,000 萬，不隨淨值縮放。

**CAGR 200% 是口氣不是目標**：複利 12.5 年 = 部位 4.14 兆、每日進出 8.3 兆，
是 2026 年全市場單日成交額（1,181 億，本機面板逐股加總）的 **7 倍**。零融資 100% 曝險下
這是定義，與策略好壞無關。把單量限制在真的填得進去的範圍，複利 CAGR 天花板實測 57.7-64.0%
（2026-11-01 用實測滑價曲線重算；之前那條手建曲線把 5% 以上參與率的成本低估一個數量級，
所以舊的 68-83% 是高估的）。

## 快速開始

```bash
# 1. 產生因子面板與 T-1 成交額（向 finlab VIP 抓最新日 K，append 後重建）

python v13_factors.py --refresh

python v13_export_model.py

# 4. 上實盤前：用真實帳戶跑一整天但零風險（會送真單，但價格不可能成交）

python v13_live_risk.py borrow     # 可借券覆蓋（已初步通過：各 gap 區間皆約 95%）

python v13_live_risk.py orders     # 盤中執行，量測 submit->ack 延遲與送單吞吐
```

## 已知限制

- 無筆數上限，筆數由資金決定：平均 34 個候選/日 → 成交 9.4 筆/日（p99 = 22、max = 26）→ 必須自動下單。量測腳本 `count_cap.py`。
- 高價股（300 元以上）常因「不足一張」被跳過，實際曝險低於模型設計值；回測已含此損耗。
- 每單位曝險的每筆邊際仍在衰退（約 −9%），v13 是用廣度與槓桿吸收，不是治好。
- 開盤 5 秒內的**成交率**尚未量測（滑價已量化：可承受額外 +0.27%/邊）。
